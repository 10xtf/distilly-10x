# Agent Note: productize the host-LLM workflow in Design V3

Status: proposed

## Problem

Design V2 established the right product boundary — local facts, multiple subjects, evidenced claims, version lineage, a zero-extra-key host path, a TypeScript engine, and a small public facade — but its specified plugin path could not execute the product acceptance test from a clean installation.

The five MCP tools had no way to create the first subject, force an immediate distillation boundary, or retrieve the material content needed to construct a draft. Pending jobs exposed only ids, hashes, and counts while hostBriefing existed only as an internal engine method. The draft let an untrusted host submit claims and unrelated Markdown as two competing truths. Evidence validation required a non-empty list but did not require the referenced material to exist, belong to the subject and generation, or contain the quoted text. A 32-bit material digest simultaneously carried identity, deduplication, evidence, and lineage. The plugin manifest assumed a distilly executable was already on PATH, and the local panel was optional even though users had no other product surface for inspecting evidence or resolving a risky candidate.

V2 also made two semantic promises that do not survive the decision to use a host LLM for research and distillation. New evidence can contradict old evidence, so profile quality does not monotonically rise with material count. Two external models can produce different evidence-bounded proposals from the same input; the deterministic obligation belongs to the engine's hashing, validation, patch application, rendering, and version transaction, not to pretending the external sampler is byte-stable.

These gaps cross the product workflow, wire contract, value types, file format, package cut, installation, review surface, and release order. Continuing to patch V2 would leave a historical design whose locked decisions mean two incompatible things. The repository's design-corpus rule exists for exactly this situation: add the next self-contained parent and preserve the old one as deprecated history.

## Proposal

[docs/design/system-v3.md](../../../../docs/design/system-v3.md) becomes the only in-force target contract. [system-v2.md](../../../../docs/design/system-v2.md) and its generated chapters remain readable, are marked deprecated, and are not rewritten to match V3.

Storage authority has one separate owner: [single-writer SQLite storage authority](../../implemented/simplification/2026-08-21-single-writer-sqlite-storage-authority.md). This aggregate note retains the overall V3 workflow, product surface, and release direction.

V3 makes the product chat-first and local-reviewable:

- The host LLM plans research, uses capabilities the host actually has, reads a typed briefing, and proposes a claim patch.
- The local engine owns subject ids, full SHA-256 content digests, material ids, deduplication, generation leases, evidence resolution, claim ids, quality summaries, deterministic Markdown, current versus suspended state, and version transitions.
- The model-facing surface keeps exactly five names: get, ingest, pending, commit, and correct. Ingest carries a discriminated create target and enqueue=now; pending carries list, brief, renew, and release. This closes the workflow without adding create, flush, research, or briefing tools.
- Briefing is the only legal host-distillation input. It atomically acquires a generation lease and returns the baseline claims, complete incremental materials, provenance, short evidence handles, prompt/schema/source-grouping versions, and explicit size limits. A full BriefContract digest is pinned in the lease and echoed by commit, so a runtime upgrade cannot silently reinterpret the host's evidence before quality is calculated. It never silently truncates.
- The host submits add, revise, supersede, and contest claim operations. It does not submit claim ids, actor, confidence, version ids, or Markdown. Claims are the semantic truth; Markdown and prompt text are deterministic projections.
- Commit hard-rejects invalid generation, lease, subject ownership, material membership, quote, locator, and patch shape. A structurally valid candidate that changes identity, loses coverage, introduces conflicts, or disagrees with a correction becomes suspended. Clean candidates become current without a compulsory click.
- The local Panel ships in the first usable release. It provides Library, Subject, Review, and Settings/Doctor pages over the same EngineClient. It renders engine-owned values, never opens persistence, and preserves the loopback, per-run token, Origin, Host, and single-write-path security boundary.
- Setup installs a versioned runtime and an absolute launcher before it writes host manifests. A fresh plugin no longer relies on a pre-existing global executable or an unpinned npx latest invocation.
- Plugin Source, Local Library, and the future remote Profile Catalog are separate concepts. The first release has no account, remote sync, publish API, or Discover placeholder. A remote catalog enters only after the local bundle, provenance, consent, moderation, and import-as-suspended contracts are proven.

MaterialId, full ContentDigest, and ProvenanceDigest are distinct; material identity is not reused as proof of source independence. Versioned normalization and source grouping keep provenance inspectable, collapse derived representations only when evidence supports it, and fail closed rather than inflating diversity.

RequestId is globally idempotent across methods and subjects: the same trusted preimage replays the stable result, while changed method, input, actor, or session authority conflicts. Privacy deletion may retain only the content-free identity needed to prevent a used RequestId from becoming a new mutation.

Privacy purge removes product-visible content and exact replay payloads without reopening a used RequestId. A same-input replay after purge returns not-found while changed input or actor remains an idempotency conflict.

Creation has a wider uniqueness boundary than later writes. The reserved People space is deterministic; exact locators outrank exact canonical display/alias candidates; ambiguity and locator disagreement fail visibly; description never proves identity. RequestId remains `req_` plus 32 lowercase hexadecimal characters.

Automatic queueing uses one auditable `auto-v1` rule: three uncommitted materials or a 30-minute-old uncommitted material, evaluated on ingest. The baseline is the current immutable version membership, and a new generation invalidates an older pending job.

An active lease carries an engine-generated per-client owner, acquisition/expiry times, generation, and the complete BriefContract. Expiry is a read-time predicate; exact brief replay returns the original bounded briefing rather than regenerating it under changed prompt, material, or capacity inputs.

The first grouping and briefing contracts are byte-addressed rather than implementation labels. `source-groups-v1` unions exact raw, private-conversation, artifact/representation locator, fallback source-URI, and content proof keys; component ids hash the sorted unique key set, while diversity eligibility uses only public artifact or fallback source-URI proof and fails closed on access conflict. The prompt version hashes the raw prompt asset together with the exact ordered evidence rules, including the model-facing prohibitions against obeying material-supplied commands or disclosing environment, configuration, secrets, and other subjects. BriefContractDigest hashes exactly the source-grouping, prompt, and draft-schema fields. Host capacity is trusted net session context, not a model parameter and not a fixed subtraction from gross context/result fields: a successful preflight must carry either a trusted handshake that directly reports the current surface's net budget or an exact host/version/environment/release/wire/canonical-skill fixture proven at the real truncation boundary. A complete compact canonical briefing uses a conservative byte-equals-token fixed point and must fit both host budgets, the 4 MiB internal cap, and 999 material references before lease acquisition.

Immutable versions own a complete claim/evidence/material-membership snapshot. VersionId hashes canonical claims with `createdIn` removed, then assigns the resulting id to claims created in that version; this preserves creation lineage without an impossible self-referential digest.

Commit has one public schema and one business transaction. Hard reject changes no product state and preserves the lease; successful current or suspended disposition consumes pending atomically with the immutable version, operation, and events. LeaseOwnerId participates in commit idempotency so a different client cannot replay another session's lease-bound mutation.

Claim application and rendering are also byte contracts. Commit rebuilds its narrow EvidenceContext from the lease-pinned baseline and material membership; it does not depend on retaining or searching a previous brief result. A canonical resolved draft deduplicates and orders evidence and observations, validates time ranges, targets each base claim at most once, and derives ClaimId from `claim-v1` plus subject and resolved draft. Empty patches are valid; add/revise create active claims, revise records the replacement edge, supersede does not invent one, and contest preserves the historical id/text/createdIn while merging evidence. Quality and review reasons use exact set/count/delta rules and canonical ordering, including suspicious/manual gates on a first version. Relations enter additively in their later slice instead of occupying a disabled runtime field.

`profile-renderer-v1` is a literal, injection-safe projection contract: seven core roots stay in fixed order, domains and claims use UTF-8 ordering, active and contested claims are explicit, superseded claims are omitted, and dynamic claim text is carried only inside canonical JSON records. Every section, combined profile, and prompt ends in one LF. The immutable version snapshots its display name and canonical review reasons, so a later subject rename cannot alter historical rendering.

The rest of the Protocol surface is closed with the same rule rather than leaving each entry point to invent validation. Random subject, space, job, lease, lease-owner, event, and capture references carry a named prefix plus 128 bits; content-derived raw, version, claim, and relation ids carry a named prefix plus a full SHA-256. Times use one UTC millisecond representation, host names and facet paths have portable ASCII grammars, and briefing evidence handles are the bounded m001..m999 namespace. Public object schemas reject unknown keys, use safe integers, and share conservative byte and collection limits for model-controlled input. JSON error details are recursively JSON-safe, while subject-creation collisions use a code-correlated typed resolution instead of an undocumented details payload. Empty EngineMethodMap results are explicit null, so in-process, disk operation records, MCP, HTTP, and later RPC do not disagree about how to serialize `void`.

The five MCP descriptors are also Protocol data, not presenter copy. One ordered registry binds each exact name to its title, local-only description, runtime input/output schemas, draft-2020-12 JSON Schemas, and all four MCP hints. Runtime and JSON schemas derive from one source and are snapshotted together. The text deliberately describes only local lookup, storage, leases, validation, commit, and correction: host research remains the outer workflow and is not falsely attributed to a tool. Get and pending actions have closed action-to-result mappings, and unknown future EngineEvent kinds fail decoding, skip handlers, and cause a full read-model refresh rather than leaking an untyped event into consumers.

V3 remains intentionally conservative about abstraction. External variation uses TypeScript interfaces: EngineClient, SourceAdapter, MaterialParser, HostCapabilityBinding, full HostBinding, HostInjector, and DraftProducer. Capability-only bindings own the one authoritative preflight; full bindings additionally create injectors/form renderers and own plugin lifecycle/doctor. Stateless algorithms are pure functions. Single production implementations are concrete services. The public API exports no abstract classes.

The package graph separates the engine from local product composition. Engine depends only on protocol and ultimately exposes a core runtime; `@distilly/runtime` composes parser registries, host bindings, doctor aggregation, and the full EngineMethodMap. File ingest remains engine-owned while runtime supplies only a narrow parser port. A vertical slice uses package-internal composition until every CoreEngineClient method has a real handler; it does not export a partial runtime or install placeholders. MCP and Panel receive actor-bound EngineClient instances and never import persistence. Request ids travel in mutation context, actor and briefing capacity come from the trusted client/session boundary, and every non-user correction receives relayed provenance and is suspended rather than labeling itself as a direct user action.

That boundary also determines the release order. Step 8 lands only the browser-safe injected-client `Distilly`/`Person` facade, the five injected-client MCP handlers, and real stdio transport conformance driven by a test-only full fake client and presenter. The fake child proves bytes, descriptors, error envelopes, and teardown; it is not a local backend, an executable product CLI, or evidence that correction and review work. Step 9 adds only binding contracts/registry, injected-provider Codex and Claude Code capability factories, conservative versioned capacity fixtures, and canonical-skill/release assembly; both concrete entries remain capability-only and report private UI capture unavailable. Recall/install later supplies injector/form-renderer implementations, and production composition alone combines those with real plugin lifecycle/doctor into full bindings. Production `distilly/node`, CLI/MCP composition, setup, and fresh-install therefore wait for a feature that first proves every Core method and full binding method has a real handler, without exporting an intermediate partial runtime. The production CLI keeps brief, editing, renewal, and commit in one foreground client session so LeaseOwnerId remains private to that session; no draft, flag, environment variable, or reconnect token persists owner authority.

The implemented Step 10 rationale lives in the [dedicated verified review and Panel feature Note](../../implemented/feature/2026-08-21-step-10-verified-review-and-panel.md).

MCP has one result and lifecycle rule across all five tools. Input, domain, presenter, and unknown implementation failures are normalized to the narrowest `WireFailure`; genuinely unknown exceptions use the redacted `internal_error` code rather than `adapter_failed` or a generic SDK error. The final Protocol output parser validates the result before the same parsed object is returned as both structured content and JSON text. Review presenters fail closed unless the returned ref and loopback review route exactly match the requested ref. Server name is fixed, version comes from the package/release build source, and EOF, signal, close, and transport error converge on bounded idempotent teardown of the owned stdio transport and MCP server while injected clients and presenters remain borrowed.

Canonical skill distribution is a recursive byte contract rather than a single-file checksum. The source root contains only regular files addressed by sorted UTF-8 POSIX relative paths; every file hashes raw bytes, and a domain-separated canonical file tuple hashes the whole tree. Assembly exact-mirrors that tree into both host roots, prunes stale targets, and writes one schema-versioned release manifest whose version is the MCP package SemVer and whose fixed host entries name the exact platform manifest and skill paths. Platform MCP templates remain source-only Step 12 inputs and cannot appear in an installable target before an absolute launcher has been rendered and smoke-tested.

The canonical skill treats trusted successful preflight plus exact five-tool availability as its entry gate. It stops before get, research, ingest, leases, or simulated fallback when that host/runtime evidence is missing; capability selection later in the workflow only consumes the already accepted result. This keeps a source plugin tree from presenting its instructions as evidence that a production runtime exists before the production-composition slice ships.

Source acquisition and private screen authorization are refined by [the private UI capture Agent Note](2026-08-20-private-ui-capture.md). That follow-on decision preserves the five-tool, host-LLM architecture while separating public research, derived text provenance, engine-owned source grouping, and a strictly consented one-to-one private-message lane.

Review cardinality is explicit: one subject has at most one active suspended target. New material may continue to ingest, but another brief/commit or rollback waits for promote, reject, or a correction that explicitly targets and replaces the candidate. A replacement keeps the current version as its parent/CAS baseline, records the old candidate as its content-derivation edge, rejects that old candidate, and creates the new current or suspended target atomically. Immutable version records retain only their created disposition; current/suspended/historical/rejected status is derived from state and events, so review does not mutate historical version files.

The initial Node support window is closed in this decision at `^22.19 || ^24`. This deliberately admits the two LTS lines exercised by the first CI matrix and rejects Node 23/25, which are EOL, plus Node 26 while it remains Current; the Node project recommends production applications use Active or Maintenance LTS releases ([Node.js releases](https://nodejs.org/en/about/previous-releases)). `22.19` is the frozen oldest fixture, not a claim that every earlier Node 22 build is known broken. Setup preflight, the CI matrix, package metadata, and both host fresh-install fixtures must move together if that support policy changes; it is no longer an implementation-time open question.

Local bundle evidence is also closed. A bundle omits complete private materials but includes the minimum shareable excerpt fact for every exported EvidenceRef. Import re-derives local MaterialIds, revalidates each quote, rewrites references, and suspends the candidate. A profile with dangling evidence is not importable.

The document generator registers V1, V2, and V3 as separate corpora and validates the entire registry before writing any chapter. Parent paths, version-directory pairs, chapter directories, and output files must be unique, and exactly one corpus must be in force. This prevents a mistaken V3 directory from silently overwriting deprecated V2 projections.

## Alternatives considered

- **Continue editing V2** — rejected because the executable workflow requires changing locked wire names and meanings, material identity, draft authority, quality semantics, panel priority, and plugin bootstrap at once. Calling both shapes V2 would hide a major break and erase why the old alternative lost.
- **Add separate create, flush, and briefing MCP tools** — rejected because the user-confirmed product surface keeps five memorable tools. Discriminated actions in ingest and pending close the same workflow without exposing internal service granularity.
- **Let the host submit a complete Profile and arbitrary Markdown** — rejected because evidence can be valid while prose invents unsupported facts. Claim patches plus deterministic rendering leave one semantic truth.
- **Leave relationOperations in DistillPatch behind a disabled feature flag** — rejected because every runtime schema and caller would prematurely own an unusable field, and a future implementation could accidentally accept then drop relation changes. The relation slice adds its discriminant, semantics, and tests together.
- **Render free-form Markdown or rebuild historical prompts from the current SubjectRecord** — rejected because model text can inject structure and later renames would mutate historical output. Canonical JSON records plus a version-time displayName make every stored profile and prompt byte-verifiable.
- **Exclude LeaseOwnerId from commit idempotency** — rejected because the same public params could then replay a mutation bound to another client session's lease. The trusted checksum includes the engine-owned owner even though the owner never appears in public params.
- **Use an LLM judge for confidence and approval** — rejected for the first release. It adds another key/cost path and still cannot guarantee consistency. The engine exposes explainable counts and mechanical review reasons; the user resolves semantic risk in the Panel.
- **Count every MaterialId, URL, OCR result, caption, or transcript as an independent source** — rejected because different material identity does not prove independent origin. Exact and provenance-linked representations remain separately inspectable but collapse into engine-owned, diversity-eligible source groups; unknown origin under-counts rather than inflates corroboration.
- **Require every candidate to be manually approved** — rejected because it turns chat-first maintenance into a click queue. Mechanical-risk candidates are suspended; clean candidates advance automatically and remain reversible.
- **Keep the Panel optional until after the SDK** — rejected because evidence and suspended versions need a trustworthy user surface. A tool-only release can create data the user cannot inspect or recover comfortably.
- **Host a remote MCP backend to qualify for a public plugin directory** — rejected because it would turn a platform distribution limitation into a cloud identity store. Local/repo distribution is the first lane; platform support can later be added in HostInstaller without changing product semantics.
- **Treat a Git repository as the whole installer** — rejected because manifests do not install the engine, resolve PATH, negotiate protocol versions, or make upgrades atomic.
- **Subtract one fixed wrapper constant from advertised host limits** — rejected because MCP returns both structured content and an escaped JSON text representation, while host ceilings may be expressed in tokens, characters, bytes, or file-reference fallback behavior. Only a directly reported net handshake or an exact versioned end-to-end truncation fixture can establish BriefCapacity.
- **Ship Step 9 “full” bindings with unsupported injector/install methods** — rejected because the kind would promise a production composition that cannot exist yet. Capability-only bindings are an explicit registry branch; later slices construct a new full registry only when every required method is real.
- **Use symlinks or a SKILL.md-only checksum to share the canonical skill** — rejected because archives and target platforms do not preserve symlinks consistently, while referenced files and assets are executable instruction context too. Release assembly exact-mirrors one recursive raw-byte tree, prunes stale targets, and records a domain-separated tree digest in the release manifest.
- **Build the remote Profile Catalog in the first version** — rejected because accounts, consent, copyright, moderation, impersonation, takedown, signatures, and update policy would delay validation of the core research-to-recall loop.
- **Use `^22.19 || >=24` as a rolling Node range** — rejected because it silently labels every future major supported before CI and host fixtures qualify it. Supporting only Node 24 was also rejected for the first release because the required CI/host matrix includes the Node 22 LTS line; adding Node 26 later is an explicit support decision, not a semver side effect.
- **Case-fold/fuzzy-match names or silently create alongside one exact name candidate** — rejected because both choices can merge or split identities without evidence. Exact versioned labels, locator disagreement, and typed remediation keep the ambiguity visible.
- **Allow arbitrary RequestId strings and normalize them independently per boundary** — rejected because it creates multiple identities for one retry. One strict 128-bit hex wire form is portable and stable across transports.
- **Keep other branded ids opaque and let each package choose regexes and limits** — rejected because ids cross protocols, URLs, exports, and transports. Divergent acceptance would make a value valid in one client and unreachable in another; one portable wire grammar and one conservative limit table are cheaper than compatibility repair.
- **Use `void` in EngineMethodMap and special-case it per transport** — rejected because JSON cannot represent undefined as a required result value. Explicit null is the smallest language-neutral result and facades may still discard it for ergonomic `Promise<void>` methods.
- **Hand-write MCP runtime schemas, JSON Schemas, titles, and annotations in the server package** — rejected because tools/list could drift from the types accepted by handlers. A single Protocol registry keeps model-facing copy local-only, schema dialect and hints reviewable, and snapshots meaningful.
- **Publish a fake-backed CLI or renamed partial workflow runtime with Step 8** — rejected because any production object typed as EngineClient promises the complete MethodMap. Returning unsupported for unimplemented methods only moves the partial-runtime failure from startup to a user call; the stdio fake remains a test fixture and no executable product entry is published until Core closure.
- **Split CLI brief and commit into independent processes and serialize LeaseOwnerId in the draft** — rejected because owner is trusted session authority, not a bearer token. A second connection receives a new owner and must conflict with the existing lease; the first CLI contract therefore keeps brief, renew, edit confirmation, and commit in one foreground session.
- **Return MCP failures through generic SDK/JSON-RPC errors or independently construct text and structured results** — rejected because callers would need two failure contracts and the two representations could drift. Every product outcome is a Protocol-parsed ToolOutput, with its JSON encoding as the only text content; only an inability to serialize even a valid WireFailure remains a protocol-level failure.

## Acceptance criteria

- Design V3 is self-contained: a first-time implementer can find the product journeys, trust boundaries, five wire schemas, value ownership, durability model, SDK methods, package tree, interfaces, pure functions, concrete services, Panel contract, installer, security constraints, migration, and release gates without consulting V2.
- The design generator creates all V3 topic chapters from the parent, marks V1 and V2 deprecated, marks only V3 in force, and fails before writing when corpus paths or outputs collide.
- HostPreflight is a closed success/failure union: success carries structured-tool capabilities, one net BriefCapacity, matching host/version/surface evidence, and warnings; failure carries no capacity/evidence and one non-retryable host_unsupported error. Codex and Claude Code capability factories consume only an injected unknown provider payload, parse and match it at runtime, report private UI capture unavailable, and never probe a user's host installation in Step 9.
- The canonical skill requires that trusted successful preflight and the exact five-tool runtime before its first get or research step; an unavailable runtime, failed preflight, false structured-tool capability, or missing tool stops without simulation, shell fallback, or global instruction writes.
- HostRegistry accepts only discriminated capability/full bindings, rejects every duplicate HostName without mutation, and lists immutable entries by UTF-8 HostName order. Injectors and form renderers have no independent registration path, and no concrete full binding exists before Recall/install plus production setup close all its methods.
- The canonical skill digest covers every regular file recursively using sorted UTF-8 POSIX paths and raw bytes. Assembly rejects symlinks, exact-mirrors and stale-prunes both host copies, writes the fixed schema-version-1 release manifest with one SemVer source and exact platform paths, and excludes unrendered MCP templates from every installable target.
- Every current authority link in root instructions, documentation maps, review guidance, development/testing guidance, and active Agent Notes points to V3 by topic. Historical statements that V2 introduced TypeScript remain historical rather than being blindly rewritten.
- After correction, Panel presentation, Core closure, and production composition exist, a fixed host fixture can execute a clean-store, no-extra-key path through exactly five MCP tool names: get(resolve/profile), ingest with create and enqueue=now, pending(brief), claim-only commit, and correct. The earlier Step 8 fake-client stdio fixture proves only adapter and transport conformance.
- Briefing contains the complete incremental generation and fails explicitly when too large. A lease acquired by one client cannot be acquired by another, expires recoverably, and becomes stale when new material arrives.
- Lease owner and full BriefContract are authoritative product state; same-request replay returns the exact stored briefing or conflicts when owner/capacity changes.
- Lease renewal preserves the same BriefContract digest; commit after a runtime upgrade either uses the pinned source-grouping/draft contract or fails explicitly when that implementation is unavailable. The same patch under different contracts cannot collide on VersionId.
- Commit rejects an unknown, cross-subject, out-of-generation, or quote-mismatched evidence reference and never writes a candidate for rejected input.
- Commit rebuilds its EvidenceContext and m001 mapping from the authoritative base/material membership under the lease-pinned algorithm, not from a brief-result lookup; 65,536 canonical patch bytes pass and 65,537 fail with zero writes, while invalid target/date/locator/evidence and unavailable pinned algorithms return their exact error codes without consuming pending or lease.
- A valid clean candidate becomes current; an identity, coverage, voice-example, contested-claim, correction, or source-diversity risk becomes suspended while the old current remains readable.
- The accepted claim-only patch has byte-stable empty/add/revise/supersede/contest semantics, canonical evidence and observedIn ordering, one operation per base claim, exact `claim-v1` ids, exact strength/quality counts, canonical gate reasons, and no relationOperations before the later relation slice.
- Claims, quality summary, Markdown, prompt, version, event, and current pointer are engine-derived and reproducible from the same accepted patch and authoritative snapshot.
- Commit success atomically consumes pending/lease, emits the version event followed by job.changed, and exact replay cannot transfer across LeaseOwnerId.
- `profile-renderer-v1` has fixed core/domain/status ordering, canonical-JSON dynamic records, injection fixtures, and one trailing LF for every artifact. Profile.displayName equals immutable VersionRecord.subjectDisplayName and historical profile/prompt bytes survive a later SubjectRecord rename.
- Each version has one complete claims/evidence/material-membership snapshot; VersionId derivation has no `createdIn` cycle.
- Different URLs with identical content remain different MaterialIds but share a source group; captions/OCR/transcripts derived from one artifact share a group; unknown provenance does not increase eligible diversity; grouping is order-independent and versioned with QualitySummary. Critical provenance changes produce distinct MaterialIds, while each version's material manifest makes its historical grouping reproducible.
- Every EngineMethodMap method has a canonical params/result type and runtime schema; mutation methods require a requestId context, and the protocol contract fixture typechecks every method and five ToolOutput envelopes.
- Every branded value has one accepted wire grammar; IsoDateTime, HostName, FacetPath, and BriefMaterialRef have boundary fixtures; all public object schemas reject unknown keys and share the same WIRE_LIMITS, safe-integer, and JSON-value rules.
- The 35 EngineMethodMap keys have an exact mutation/query partition and JSON-round-trippable results; empty success is always null.
- tools/list returns exactly the ordered five-registry descriptors, including reviewed title/description copy, draft-2020-12 input/output schemas, and readOnly/destructive/idempotent/openWorld hints; get and pending actions cannot return another action's success shape.
- Every MCP call returns the one output-parser-validated ToolOutput in structured content and its exact JSON encoding in text content; invalid, domain, presenter, and unexpected outcomes use typed WireFailure results, with unknown exceptions redacted to non-retryable `internal_error`. The server name/version source, exact ReviewLaunch ref/route, borrowed-client ownership, and bounded idempotent EOF/signal/transport-error teardown have transport-level fixtures.
- already_exists returns one typed subject, ambiguous_subject returns at least two typed candidates, and other errors cannot carry subject resolution or non-JSON details. An unknown EngineEvent is not delivered to a handler and causes a schema_unsupported full reread.
- Two concurrent clients creating the same identity in one space cannot both succeed; People/bootstrap, inline-space resolution, exact duplicate rules, and malformed or reused RequestIds are deterministic.
- MCP, Panel, and CLI can share one local runtime only after production composition exists, while retaining host/user actor identity and a distinct engine-owned lease owner per client; Panel materials and doctor views use typed methods rather than opening persistence.
- Once all core handlers exist, the production runtime is constructible without callers importing internal repositories; earlier slices keep composition internal, and file ingest crosses only a narrow parser port.
- The production CLI's `distill` command holds one process, client session, LeaseOwnerId, and stable commit RequestId across brief, draft editing, renew, and commit. Its current-user-only envelope omits owner authority, detects briefing snapshot changes, and cannot be resumed by a second process that merely knows the lease id.
- At most one suspended target exists per subject; stale-parent promotion and rollback during active review fail with review_conflict; candidate replacement records its separate derivation edge; immutable versions are not rewritten by promote/reject.
- MCP correct has no unreachable current branch, while host/sdk/executor/system correction is mechanically suspended with relayed provenance and user correction retains direct-user provenance.
- Exported bundle claims have locally verifiable excerpt evidence after import; no dangling external MaterialId survives.
- The first usable release cannot be declared before fresh-install setup, both host bindings, the local Panel, security refusal tests, and next-chat Recall pass from built artifacts.
- The first release performs no Distilly account login, Profile Catalog network call, hidden sync, background executor start, or telemetry upload.

## Risks

- V3 is deliberately detailed and can be mistaken for shipped behavior. Every entry document must retain the target-versus-live distinction, and architecture.md must change only with implementation.
- Step 8 can look executable because its tests launch a real stdio child, but that child deliberately injects fake dependencies and is not a usable Distilly runtime. Package exports, binary manifests, architecture claims, setup, and fresh-install gates must preserve that distinction until production composition lands.
- A claim-only deterministic renderer may initially sound less polished than free prose. The mitigation is to improve claim quality and renderer templates while keeping every factual sentence traceable, not to restore a second unconstrained prose truth.
- The 30-minute first lease may be wrong for some hosts. The returned expiry and renew action make the behavior visible; changing the internal default within the same semantic contract does not require a wire break.
- Incremental briefing retains baseline claims instead of every historical material body. A revision that needs an old quote can retain the existing EvidenceRef; a full semantic reconsideration is an explicit, size-bounded redistill. Tests must catch accidental claim loss.
- Auto-v1 has no timer, so a two-item set older than 30 minutes queues only on the next ingest attempt, including a duplicate-only attempt. The product must describe this as attempt-driven batching rather than implying a background executor exists.
- Conservative wire limits can reject an unusually large single material, correction, patch, or briefing even when a particular host could carry it. The product must return the exact failed boundary and remediation; raising a shared limit requires updating both runtime and JSON schema snapshots, while large research sets should be split across ingest calls rather than silently accepted by only one entry point.
- Importing a public bundle as suspended adds friction. Trusting a remote profile directly as local current would be worse because provenance policy, moderation, and publisher identity are outside the local engine's authority.
- Platform plugin rules can change. V3 isolates current distribution facts in the plugin chapter and keeps the engine independent, but release maintainers must re-check official host documentation before publishing.
- Superseding all current authority links is a wide documentation diff. Mechanical link and generated-chapter gates do not prove the prose is still historically accurate, so the final review must distinguish live authority from historical V2 references.
