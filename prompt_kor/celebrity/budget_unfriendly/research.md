# Celebrity Budget-Unfriendly Research Prompt

## 과제

근거 엄밀성을 최대로 끌어올린 심층 다차원 공개 인물 조사를 수행한다.

이 모드는 의도적으로 비싸다. 사용자가 더 높은 확신도의 skill을 원하고 느린 워크플로를 감수할 때만 사용해야 한다.

목표는 단순히 노트를 모으는 것이 아니다. 다음을 할 수 있을 만큼 근거 있는 증거를 확보하는 것이 목표다:
- 이후의 audit, synthesis, validation 단계를 통과할 것
- 이 사람의 실제 인지 운영체계를 재구성할 것
- 그의 진짜 사고 패턴을 일반적 통찰과 구분할 것

---

## 선별 원칙

무엇을 수집하고 무엇을 건너뛸지는 다음 원칙을 따른다. 모든 단계에 적용된다.

1. **장문 > 단편**: 3,000단어 에세이 하나가 트윗 50개보다 사고 구조를 더 많이 드러낸다
2. **논쟁 > 합의**: 논란이 된 입장이 모두가 칭찬하는 입장보다 그 사람 고유의 사고를 더 잘 드러낸다
3. **변화 > 고정**: 생각을 바꾼 지점이 일관되게 유지한 지점보다 정보량이 많다
4. **1차 > 2차**: 본인의 말이 언제나 남의 요약보다 우선한다
5. **작업 방식에 대한 논의 > 전기**: 자기 프로세스를 어떻게 이야기하는지가 생애사보다 중요하다
6. **반복 패턴 > 일회성 인용**: 여러 맥락에서 5번 나타나는 패턴이 바이럴된 문장 하나보다 낫다
7. **실패에 대한 논의 > 성공 서사**: 무엇이 잘못됐는지 말하는 방식이 승리의 회고보다 더 많이 드러낸다

## 출처 품질 위계

다음 순서를 엄격히 지켜 출처를 우선한다:

1. **사용자가 제공한 로컬 자료** (전사본, PDF, 스크린샷 — 기준값, 최고 가중치)
2. **1인칭 저작물** (책, 에세이, 뉴스레터, 블로그 글)
3. **장문 인터뷰와 대담** (30분 이상 팟캐스트, 영상 인터뷰, 파이어사이드 챗)
4. **기록된 의사결정과 전환점** (사례 연구, 공개 기록, 출처가 명시된 보도된 행동)
5. **단문 1인칭 콘텐츠** (소셜 미디어 게시물, 짧은 Q&A, 트윗 스레드)
6. **외부 분석과 비평** (프로필 기사, 서평, 타인이 쓴 전기)
7. **2차 요약** (1차 출처를 찾기 위해서만 사용하고, 단독 근거로는 절대 쓰지 않는다)

### 출처 블랙리스트 — 영구 제외

**중국어권:**
- Zhihu — 검증 불가능한 익명 답변, 전언이 많음
- WeChat 공식 계정 — 대부분 2차 콘텐츠를 재포장한 것
- Baidu Baike — 신뢰할 수 없고, 오래되었거나 홍보성인 경우가 많음
- Sohu / NetEase / Tencent 의 자동 생성 뉴스 집계 페이지

**한국어권:**
- 지식iN 등 Q&A 게시판 — 검증 불가능한 익명 답변
- 나무위키 — 사용자 편집이고 출처 표기가 없거나 서술이 편향된 경우가 많다
- 보도자료를 그대로 옮긴 기사 — 1차 자료가 아니라 홍보물 재배포다
- 인터뷰 발췌만 싣고 전문을 링크하지 않은 기사

**공통:**
- 콘텐츠 팜과 SEO 최적화된 요약 사이트
- AI가 생성한 인물 소개 페이지
- 리스티클 ("X에게서 배우는 10가지 교훈") — 1차 출처를 직접 인용하고 링크한 경우 제외
- 단독 근거로서의 Wikipedia (실제 출처를 찾기 위한 길잡이로만 허용)
- 그 자체가 요약의 요약인 모든 출처

**영어권 인물:**

- 개인 블로그와 뉴스레터 (Substack, 개인 사이트)
- 출간된 저서와 에세이
- 타임스탬프가 있는 팟캐스트 전체 회차
- 권위 있는 프로필 기사: New Yorker, Atlantic, Bloomberg, Wired, NYT, FT

### 자막 없는 오디오·영상 다루기

심층 모드에서는 가장 풍부한 항목(대담, 표현 DNA) 중 일부가 긴 오디오/영상 출처에
기반할 것을 기대한다. 이 Skill은 외부 서비스를 호출하지 않으므로, 자막이 없으면
사용자가 전사본이나 발췌를 직접 제공해야 한다.

작업 흐름:

1. 전사본은 skill 디렉터리 밖의 임시 경로에 둔다.
2. 전사본을 한 번 읽고, 타임스탬프와 함께 의역한 발견 사항을 추출한다.
3. `knowledge/research/raw/` 에는 의역 노트와 출처 메타데이터만 기록한다.
4. 원본 전사본을 폐기한다. skill 디렉터리에는 긴 축어 전사본이 절대 있어서는 안 된다.
   저작권 안전을 위반하고 audit에서 불합격한다.

사용자가 전사본을 제공할 수 없으면, 조용히 항목을 건너뛰지 말고 그 공백을 명시적으로 알린다.

### 단문 1인칭 게시물

단문 1인칭 게시물이 특정 공백을 메워 줄 때는 사용자가 퍼머링크나 발췌를 직접 제공해야
한다. 자동 수집 도구는 제공하지 않는다. 작성자를 검증하고 각 퍼머링크를 열어 본 뒤
선택한다. 관련 근거만 안전하게 의역해 알맞은 트랙에 넣고, 개별 URL·접근 일자·근거
수준·출처 가중치를 보존한다.
후보 파일, 검색 페이지, 프로필 루트는 절대 근거 있는 출처로 세지 않는다.

## 6개 항목 병렬 수집

조사는 반드시 독립적인 6개 항목을 다뤄야 한다. 각 항목은 자체 전용 파일을 만든다.
항목을 병합하거나 파일 간에 관찰을 복제하지 않는다.
이 여섯 파일을 하나의 통합 스크래치패드로 대체하지 않는다.

### 항목 1: 저술

**파일**: `01_writings.md`

**대상**: 본인이 직접 쓴, 체계적이고 숙고된 입장. 발표 전에 생각할 시간이 있었던 것.

검색하고 기록할 것:
- 저서 (요약이 아니라 챕터별 핵심 논증)
- 에세이, 블로그 글, 뉴스레터
- 공개된 편지, 메모, 내부 문서
- 여러 저술에 걸쳐 반복되는 핵심 주장
- 그의 서면 논증이 시간에 따라 어떻게 변해 왔는지

**추출 초점**: 핵심 명제, 추론 사슬, 논증을 구조화하는 방식, 반복해서 쓰기로 선택하는 주제.

### 항목 2: 대담

**파일**: `02_conversations.md`

**대상**: 즉석에서 어떻게 사고하는가. 대화 중에, 압박 속에서, 준비할 수 없을 때.

검색하고 기록할 것:
- 장문 팟캐스트 출연 (30분 이상, 전체 회차 선호)
- 실질적인 주고받기가 있는 영상 인터뷰
- 패널 토론과 논쟁 (특히 그가 이견을 내는 경우)
- 청중이 예상치 못한 질문을 던지는 AMA / Q&A 세션
- 적대적이거나 불공정한 질문에 대응하는 방식

**추출 초점**: 즉흥적 추론, 예상 밖 상황을 다루는 방식, 반박당했을 때 되돌아가는 지점, 이견을 표현하는 방식.

### 항목 3: 표현 DNA

**파일**: `03_expression_dna.md`

**대상**: 언어적 지문. 이름이 없어도 그를 알아볼 수 있게 만드는 패턴.

서로 다른 출처 사례 최소 5개에 걸쳐 분석한다:
- 문장 리듬: 평균 길이, 변주, 조각 문장 vs 복문의 사용
- 비유 목록: 어떤 영역에서 유추를 끌어오는가?
- 이견 구성: 정면 대립인가? 재구성인가? 유머인가? 일축인가?
- 압축 수준: 전부 설명하는가, 청중의 전문성을 가정하는가?
- 확신 언어: 확신과 의심을 어떻게 표현하는가?
- 반복되는 표현, 말버릇, 고유한 프레이밍
- 유머 스타일 (있다면): 자조적, 부조리, 건조함, 공격적, 냉소적
- 어조 전환: 가벼운 맥락과 진지한 맥락 사이에서 목소리가 어떻게 달라지는가?

**추출 초점**: "블라인드 테스트"를 통과하는 스타일 표지. 이름을 지운 100단어로 이 사람을 알아볼 수 있는가?

### 항목 4: 의사결정

**파일**: `04_decisions.md`

**대상**: 하겠다고 말한 것이 아니라 실제로 한 것.

검색하고 기록할 것:
- 큰 베팅: 시간/돈/평판을 어디에 투자했고 그 근거는 무엇인지
- 방향 전환: 어디서 방향을 바꿨고 무엇이 계기였는지
- 트레이드오프: 무엇을 위해 무엇을 희생하기로 명시적으로 선택했는지
- 실패: 무엇이 잘못됐는지 어떻게 이야기하는지 (또는 이야기를 피하는지)
- 채용 / 팀 결정: 누구와 일하기로 선택했고 그 이유는 무엇인지
- 타이밍 결정: 언제 빠르게 움직였고 언제 기다렸는지

**추출 초점**: 의사결정 패턴, 리스크 감수 성향, 어떤 근거가 그를 움직이는지, 표명한 가치와 드러난 선호 사이의 간극.

### 항목 5: 외부 시각

**파일**: `05_external_views.md`

**대상**: 다른 사람들의 머릿속에 존재하는 이 인물의 버전. 특히 본인의 자기 서사와 갈리는 지점.

검색하고 기록할 것:
- 실질적인 비판 (인신공격이 아니라)
- 신뢰할 만한 관찰자가 지적한 모순
- 협업자, 반대자, 후임자가 그를 묘사하는 방식
- 같은 분야 동료들이 짚어낸 알려진 맹점
- 뻔하지 않은 무언가를 드러내는 칭찬
- 공적 이미지와 보도된 사적 행동 사이의 간극

**추출 초점**: 외부 시각이 내부 시각과 갈리는 지점. 본인은 못 보고 남들은 보는 것.

### 항목 6: 타임라인

**파일**: `06_timeline.md`

**대상**: 언제 무슨 일이 있었는지의 이력서가 아니라, 사고가 어떻게 변해 왔는가.

다음을 추적하는 타임라인을 구성한다:
- **인지적 영향**이 있었던 주요 이정표 (이 사건이 그의 사고를 어떻게 바꿨는가?)
- 지적 전환점 — 핵심 신념이 언제 이동했는가?
- 국면 전환: 그의 사고에 뚜렷이 구분되는 시기가 있었는가?
- 최근 동향 (최근 12-24개월)
- 예전에는 믿었지만 이제는 믿지 않는 것

**추출 초점**: 연대기적 전기가 아니라 인지적 변화의 궤적.

## 자료 부족 인물 프로토콜

조사 중 여러 항목의 자료가 매우 얇다는 것을 발견하면:

1. 공백을 메우기 위해 근거, 인용문, 귀속을 **지어내지 않는다**
2. 얇은 각 항목마다 무엇이 없고 왜 없는지를 **명시적으로 표기한다**
3. **근거 있는 출처 총계를 센다**: 10건 미만이면 자료 부족 인물이다
4. 자료 부족 인물의 경우:
   - 멘탈 모델을 최대 2-3개로 제한한다
   - 얇은 모든 항목에 "제한된 정보 기반" 표기를 추가한다
   - 정직한 한계 섹션을 대폭 확장한다
   - 어떤 자료를 구체적으로 추가하면 품질이 좋아지는지 사용자에게 알린다
   - 계속 진행할지, 아니면 자료가 더 잘 남아 있는 인물로 바꾸도록 권할지 검토한다

## 필수 산출물 계약

`knowledge/research/raw/` 아래에 raw 조사 노트 파일 6개를 만든다:

- `01_writings.md`
- `02_conversations.md`
- `03_expression_dna.md`
- `04_decisions.md`
- `05_external_views.md`
- `06_timeline.md`

각 파일은 다음을 포함해야 한다:

```md
# <항목 제목>

## Collection Metadata
- 항목: [번호와 이름]
- 수집 전략: [웹 전용 / 웹+로컬 / 로컬 우선]
- 검색한 출처: [개수]
- 사용한 출처: [개수]
- 1차 대 2차 비율: [X:Y]

## Source Metadata
(각 출처마다 반복)
- URL: ...
- 출처 유형: 책 / 에세이 / 인터뷰 / 팟캐스트 / 강연 / 소셜 게시물 / 기사 / 프로필 / 의사결정 기록
- 근거 수준: 1차 / 2차
- 접근 메모: 공개 / 부분 / 차단됨
- 출처 가중치: [1-7, 위 위계 기준]
- 날짜: [발행일 또는 접근일]

## Evidence

- ...

- ...

- ...

```

### 최소 품질 기준 (budget-unfriendly)

6트랙 세트 전체를 통틀어:

- raw 노트 파일 최소 6개 (항목당 1개)
- 근거 있는 출처 URL 최소 8개
- 1차 출처 표기 최소 3건
- 출처 메타데이터 블록 최소 6개 (파일당 최소 1개)
- 세트 전체에 걸쳐 모순 항목 최소 6개
- 세트 전체에 걸쳐 추론 항목 최소 6개
- 긴 인용 가능성이 있는 줄 0개 (저작권 안전)
- 트랙 커버리지 = 6 (건너뛴 항목 없음)

근거 있는 URL은 실제로 열어 본 페이지여야 하며, 플랫폼 루트나 자리 표시용 경로는 안 된다.

### 각 트랙을 구분되게 유지한다

- 같은 관찰을 여섯 파일에 복제해 넣지 않는다
- 각 항목에는 고유한 추출 초점이 있다. 그것을 지킨다
- 어떤 발견이 여러 항목에 걸쳐 있으면, 가장 관련 있는 파일에 주요 근거를 두고 나머지 파일에는 상호 참조 메모를 남긴다

## Audit 준비 상태

여섯 번째 파일이 존재한다고 해서 조사가 끝난 것이 아니다. 6트랙 세트가 별도의 research audit을
통과할 만큼 충분히 강해 보일 때 비로소 끝난 것이다.

넘어가기 전에, 노트가 다음을 뒷받침하는지 확인한다:

- 항목을 교차하는 근거를 가진 멘탈 모델 후보 3개 이상
- 근거 기준점이 있는 known-answer 질문 후보 2개 이상
- 외삽을 요구하는 신뢰할 만한 경계 사례 질문 1개 이상
- 실질적 긴장 3건 이상이 담긴, 눈에 보이는 모순 목록
- 블라인드 스타일 테스트를 통과할 만큼의 표현 DNA 샘플

## 조사 규칙

- 논평보다 1인칭 자료를 우선한다
- 짧은 클립보다 장문 인터뷰를 우선한다
- 일회성 자극적 인용보다 반복 패턴을 우선한다
- 얕은 전기보다 작업 방식, 선택, 트레이드오프에 대한 직접적 논의를 우선한다
- 출처 공백을 정직하게 기록한다. 공백도 정보다
- 실제로 열어서 확인한 URL만 기록한다
- 일반 홈페이지, 주제 페이지, 검색 페이지, 자리 표시용 미디어 루트는 세지 않는다
- 각 트랙을 의미 있게 다르게 유지한다. 각 항목에는 고유한 추출 초점이 있다
- 이후의 known-answer 및 경계 사례 검증을 위한 근거를 충분히 쌓는다

## 저작권 안전

- 전체 전사본을 저장소에 쓰지 않는다
- 책, 자막, 기사의 긴 발췌를 붙여 넣지 않는다
- 직접 인용은 아주 짧게 유지한다 (2문장 미만)
- 출처를 밝히고 자기 표현으로 요약한다
- 자막 덤프, 전사본 형태의 블록, 길게 복사한 대화를 저장하지 않는다
