# 기본 정보 입력 스크립트

## 오프닝

```
이 동료의 Skill을 만들어 드리겠습니다. 질문 3개만 답하시면 되고, 각 질문은 건너뛸 수 있습니다.
```

---

## 질문 순서

### Q1: 별칭/코드명

```
이 동료를 어떻게 부르나요? (별칭, 닉네임, 코드명 모두 가능. 여러 단어는 - 로 연결)

예: 홍길동 또는 gil-dong
```

- 임의의 문자열을 받는다
- 생성되는 slug는 `-` 로 통일해 연결한다 (밑줄은 쓰지 않는다)
- 한글은 국어의 로마자 표기법에 따라 자동 변환된다 ("홍길동" → `hong-gil-dong`)
- 영어는 소문자로 바꿔 `-` 로 연결한다 ("Big Mike" → `big-mike`)
- 관용 표기를 쓰려면 (예: 이 → `lee`) 로마자를 직접 적는다.
  자동 변환은 표기 일람을 그대로 적용하므로 이 → `i` 가 된다

---

### Q2: 기본 정보

회사, 직급, 직위, 성별을 한 질문에 넣어 사용자가 한 문장으로 답하게 한다:

```
그의 기본 정보를 한 문장으로 설명해 주세요. 회사, 직급, 직위, 성별 중 떠오르는 대로 쓰시면 되고 건너뛰어도 됩니다.

예: OO플랫폼 책임 백엔드 엔지니어 남
```

사용자의 답변에서 다음 필드를 파싱한다 (없으면 비워 둔다):
- **회사**
- **직급**
- **직위**
- **성별**

#### 직급 표기 참고

- 회사가 쓰는 직급 표기를 **그대로** 받아 적는다 (예: "책임", "3급", "G4", "Staff").
  다른 회사 체계로 임의 환산하지 않는다
- 표기만으로 담당 범위를 알 수 없으면 아래 단계 중 어디에 해당하는지 한 번 더 묻는다

| 단계 | 판단 기준 |
|------|---------|
| 주니어 | 지시받은 범위를 수행한다. 설계 판단은 위임한다 |
| 미들 | 맡은 기능을 독립적으로 설계하고 끝낸다 |
| 시니어 | 여러 기능의 설계를 주도하고 남의 산출을 리뷰한다 |
| 리드 · 책임 | 팀 단위 기술 방향과 우선순위를 정한다 |
| Staff · Principal | 조직 경계를 넘는 기술 결정을 한다 |

> 이 단계 구분은 Persona 의 어조와 판단 범위를 잡는 데만 쓴다.
> 회사별 직급 체계 환산표는 두지 않는다. 회사마다 기준이 달라
> 근거 없는 대응표가 되기 때문이다.

### Q3: 성격 프로필

MBTI, 별자리, 개성 태그, 조직문화 태그, 주관적 인상을 모두 합쳐 사용자가 자유롭게 서술하게 한다:

```
그의 성격을 한 문장으로 설명해 주세요. MBTI, 별자리, 개성, 몸에 밴 조직문화, 본인이 받은 인상 중
떠오르는 대로 쓰시면 되고 건너뛰어도 됩니다.

예: INTJ 염소자리 책임 회피 선수 맥락 우선 직설형 CR은 아주 엄격한데 이유는 절대 설명 안 함
```

사용자의 답변에서 다음 필드를 식별해 추출한다 (없으면 비워 둔다):
- **MBTI**: 16가지 표준 유형
- **별자리**: 12별자리
- **개성 태그**: 아래 태그 목록에서 매칭하고, 직접 서술한 표현도 받는다
- **조직문화 태그**: 아래 태그 목록에서 매칭한다
- **주관적 인상**: 분류할 수 없는 자유 서술은 원문 그대로 보존한다

#### 개성 태그 목록

**업무 태도**: 성실 책임감 / 대충 넘어감 / 책임 회피 선수 / 총대 메는 사람 / 완벽주의 / 미루기

**소통 스타일**: 직설적 / 빙빙 돌림 / 말수 적음 / 말수 많음 / 음성 메시지 애용 / 읽고 답 안 함 / 읽고 엉뚱하게 답함 / 즉답 강박

**의사결정 스타일**: 결단력 있음 / 말 바꾸기 반복 / 상급자 의존 / 강하게 밀어붙임 / 데이터 기반 / 전적으로 감

**감정 스타일**: 감정 안정 / 유리 멘탈 / 쉽게 흥분 / 냉담하고 거리 둠 / 겉으로만 원만 / 비꼬는 말투

**화법과 수단**: PUA 선수 / 사내 정치 플레이어 / 책임 전가의 달인 / 상향 관리 전문가 / 훈계 좋아함 / 감정적 압박

#### 조직문화 태그 목록

- **맥락 우선 직설형** — 말을 꺼낼 때 배경부터 정렬하고, 방안을 보면 먼저 "impact가 뭐냐"고 물음. 직설적인 것을 미덕으로 봄
- **방법론 프레임형** — 문제를 말할 때 프레임워크부터 꺼냄. "임파워먼트", "지렛대", "선순환 구조" 같은 사내 용어를 즐겨 씀
- **데이터 선행형** — 데이터로만 말함. 같은 일을 두 안으로 병행해 비교함. 보수적이고 사용자 경험을 중시함
- **절차·보고 중시형** — 느려도 절차를 밟는 것이 옳다고 봄. 보고 자료를 정교하게 만듦. 실행력을 강조함
- **기술 위계형** — 기술 우위를 기준으로 상대를 평가함. 위계 의식이 강하고 정보를 쉽게 공유하지 않음
- **실행 압박형** — 극한의 실행력으로 디테일에 집착함. 결과 지향이며 과정은 중요하지 않다고 봄
- **제1원리형** — 본질을 파고들고, 유추 추론을 거부하며, 과감하게 단순화함
- **OKR 신봉자** — 무슨 일이든 Objective부터 묻고, KR을 두고 깐깐하게 따짐
- **대기업 조립라인** — 규범은 잘 갖춰져 있으나 창의성은 낮음, SOP 의존, 책임지기를 두려워함
- **스타트업파** — 자원 부족, 풀스택 사고, 결과 지향, 혼란을 감내함
