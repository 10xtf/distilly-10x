# 증분 Merge Prompt

## 과제

다음을 받게 된다:
1. 기존 `work.md` 내용
2. 기존 `persona.md` 내용
3. 새 원자료 내용 (파일 또는 메시지)

새 내용이 어느 부분을 갱신해야 하는지 판단하고, 증분 갱신 내용을 출력하는 것이 과제다.

**원칙: 증분만 추가하고 기존 결론을 덮어쓰지 않는다. 충돌이 있으면 충돌 알림을 출력해 사용자가 결정하게 한다.**

---

## Step 1: 분류 판단

새 내용의 각 정보를 분류한다:

| 정보 유형 | 귀속 |
|---------|------|
| 기술 규범, 코드 스타일, 인터페이스 설계, 업무 프로세스 | → work.md |
| 업무 지식, 시스템 담당 범위, 기술적 결론 | → work.md |
| 소통 스타일, 입버릇, 표현 습관 | → persona.md |
| 의사결정 행동, 대인관계, 감정 패턴 | → persona.md |
| 양쪽 모두 해당 | → 각각 귀속 |

---

## Step 2: 충돌 검사

새 내용과 기존 내용을 대조한다:

- 새 내용이 기존 정보를 **보완**하면 (새 디테일 추가) → 그대로 추가
- 새 내용이 기존 정보를 **확인**해 주면 → 무시한다 (중복해서 쓰지 않는다)
- 새 내용이 기존 정보와 **모순되면** → 충돌 알림을 출력한다:

```
⚠️ 충돌 발견:
- 기존: {기존 서술}
- 새로 발견: {새 내용 서술}
- 출처: {파일명/시각}

권고: [기존 유지 / 새 내용으로 갱신 / 둘 다 유지하고 시각 표기]
사용자가 결정하게 한다.
```

---

## Step 3: 갱신 Patch 생성

`work.md` 갱신은 다음 형식으로 출력한다:
```
=== work.md 갱신 ===

["기술 규범/네이밍 규칙" 절에 추가]
- {새 내용}

["경험 지식" 절에 추가]
- {새 지식 결론}

[갱신 없음] 또는 [위 장절에 갱신 있음]
```

`persona.md` 갱신은 다음 형식으로 출력한다:
```
=== persona.md 갱신 ===

["Layer 2/어휘 습관" 절에 추가]
- 새 입버릇: "{xxx}"

["Layer 4/동급자에게" 절에 추가]
- {새 행동 서술}

[갱신 없음] 또는 [위 장절에 갱신 있음]
```

---

## Step 4: 갱신 요약 생성

사용자에게 다음을 보여 준다:
```
이번 갱신 요약:
- work.md: 새 정보 {N}건 추가 ({간단한 설명})
- persona.md: 새 정보 {N}건 추가 ({간단한 설명})
- 충돌 {N}건 발견, 확인 필요 (위 참조)

버전은 {vN} 에서 {vN+1} 로 올라간다.
갱신을 적용할까요?
```
